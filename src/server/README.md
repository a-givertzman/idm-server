# IDM Protocol & Client Architecture (MVP)

Событийная модель взаимодействия между Клиентом и Сервером.

**Структура посылки**:

Field name | Start |  Id   | ContentKind | Cot  | OperationId |  Size  | Data       |
---        |  ---  |  ---  | ---         | ---  | ---         |  ---   | ---        |
Data type  |  u8   | u32   | u8          | u8   | u32         | u32    | [u8; Size] |
Value      |  22   | 111   | 02          | 04   | 12          | xxx    | [..., ...] |

- `Start` - Each message starts with SYN (22)
- `Id` - Идентификатор сообщения
- `ContentKind` - Вид данных в поле `Data`
    - 01, Empty
    - 02, Bytes
    - 38, Json
    - 40, String
- `Cot` - Причина и направление передачи
- `OperationId` - Идентификатор операции
- `Size` - Длина поля `Data` в байтых
- `Data` - Данные

Cot — мета-информация передачи..
OperationId — идентификатор операции.
Operation — смысл.


## 1. Общая цель

Зафиксировать и унифицировать модель взаимодействия клиента и сервера:

* Чёткое разделение слоёв
* Независимость transport (сетевые сообщения) от domain (сущности приложения)
* Расширяемость через `Operation` (Сущности приложения...Запросы, Команды, Ответы)
* Причина передачи `Cot` относится к уровню transport не расширяется приложением

---

# 2. Архитектурные уровни

```
TCP Stream                           |    Сетевой обмен
   ↓
Message                (parser)      |    Разбор сообщений
   ↓
Frame<OperationId>    (transport)    |    Структурирование и распределение сообщений
   ↓
Operation           (domain object)  |    Сущности уровеня приложения
```

---

# 3. Transport Layer

## 3.1 Message (Parser)

Ответственность:

* Чтение TCP-потока
* Сборка байтов в структуру Frame
* Валидация целостности

### Гарантии

* Не знает Operation
* Не знает JSON
* Не знает Domain-логику
* Не знает бизнес-смысл

---

## 3.2 Frame<OperationId>

Transport DTO

Содержит:

* `id` — уникальный идентификатор сообщения
* `cot` — причина и направление передачи
* `kind` — тип контента (Empty / Bytes / Json)
* `operation_id` — идентификатор операции
* `size`
* `payload: bytes`

### Гарантии

* Frame не знает структуру Operation
* Frame не знает бизнес-логику
* Frame не содержит десериализованные данные

---

## 3.3 Cot (Cause Of Transmission)

Зачем и в каком направлении передаётся сообщение. Закрытый enum протокола.
- Inf      — спонтанное сообщение
- Req      — запрос, требующий ответа
- ReqCon   — подтверждение запроса
- ReqErr   — ошибка обработки запроса
- Cmd      — команда
- CmdCon   — подтверждение команды
- CmdErr   — ошибка выполнения команды

* Классификация направления и причины передачи
* Не несёт бизнес-семантики
* Не расширяется приложением

---

# 4. Protocol Boundary

## 4.1 OperationId (OperationId)

Расширяемый идентификаторов операций протокола.

* Точная идентификация операции
* Используется для выбора обработчика
* Часть протокола, не бизнес-логики

OperationId отвечает на вопрос:

> Что это за операция?

---

## 4.2 Operation

Сущности приложения (Domain-уровень).

Каждая операция:

* Имеет связанный `OperationId`
* Знает, как сериализоваться/десериализоваться
* Определяет тип ответа

---

## 4.3 Преобразование

Граница протокола:

```
Frame<OperationId> → Operation
```

Через:

```
frame.operation<Operation>() -> Result<Operation>
```

На этом этапе:

* Проверяется соответствие `Operation::ID == frame.operation_id`
* Производится десериализация payload
* Transport больше не участвует

---

# 5. Ответственность слоёв

| Слой        | Знает о                | Не знает о          |
| ----------- | ---------------------- | ------------------- |
| Message     | TCP, bytes             | Cot, Operation      |
| Frame       | Cot, OperationId, bytes       | Operation структура |
| Cot         | направление передачи   | бизнес-логика       |
| OperationId | идентификатор операции | payload             |
| Operation   | бизнес-смысл           | TCP                 |

---

# 6. Архитектурные принципы

1. Transport не зависит от Domain.
2. Domain не зависит от TCP.
3. Cot не используется для бизнес-логики, не расширяется на уровне приложения
4. OperationId — единственный точный идентификатор операции.
5. Расширяемость достигается через добавление новых Operation.

---

# 7. MVP Ограничения

* Cot фиксирован и закрыт.
* OperationId может расширяться.
* Frame остаётся универсальным контейнером.
* Десериализация происходит лениво, на границе протокола.
